01 / INPUT

Where the player list comes from

Prowl keeps a roster of names it is meant to display and check. In a Bed Wars waiting lobby or active match, /pr who reads the names supplied by the server's /who response. During a match it can also use the current Minecraft tab entries. /pr add <name> adds one chosen player, including someone who is not currently in your tab list.

In Bed Wars waiting lobbies, ordinary public player chat can add the speaker to the roster. Party, guild, officer, and other non-player chat lines are ignored. In a waiting lobby, the current player list is not automatically treated as a game roster. Roster entries are removed when the game ends or the server sends a transfer message; /pr clear clears the tracked roster.

Identity matchingWhen Minecraft already provides a player's UUID, Prowl uses it directly. If a manually added name has no live tab entry, Prowl asks Mojang's profile service to resolve the name to a UUID and canonical capitalization.

02 / BED WARS DATA

Hypixel stats lookup

For each roster player whose cached data has expired, Prowl queues a player-profile request to Hypixel. It sends the player's UUID without hyphens and supplies the API key in the API-Key request header.

GEThttps://api.hypixel.net/v2/player?uuid=<uuid>

The response's player.stats.Bedwars record provides the values shown in the tab:

  • Level: derived from Bed Wars Experience, using the prestige XP thresholds.
  • FKDR: final_kills_bedwars ÷ final_deaths_bedwars.
  • WLR: wins_bedwars ÷ losses_bedwars.
  • WS: the Bed Wars winstreak field.
  • Rank: rank fields from the player profile, including the player's configured MVP+ color.

If a denominator is zero, Prowl displays the available numerator as the ratio. A missing Bed Wars record is shown as no record. A profile response without a player object is treated as hidden/nicked, so Prowl does not try to identify a nicked account.

Names without a known UUID are resolved with Mojang's profile endpoint:

GEThttps://api.mojang.com/users/profiles/minecraft/<name>

Player-head textures are fetched separately from Mojang's session profile and texture service. A skin failure does not block the stats row.

03 / TAG DATA

Urchin tag lookup

Urchin checks only the current Prowl roster. Prowl gathers UUIDs from Minecraft's player list or its name-to-UUID cache, then sends all uncached UUIDs together in one JSON request:

POSThttps://api.urchin.gg/v3/players
{ "uuids": ["uuid-with-hyphens", "another-uuid"] }

The request uses Content-Type: application/json, Accept: application/json, and the Urchin API key in the X-API-Key header. The response is read from its players object, keyed by UUID. For each returned tag, Prowl reads tag_type (or type) and the optional reason.

Those fields determine the tag icons in the Urchin column. The tag-type matcher recognizes sniper, confirmed, caution, closet/closer, blatant, legit-sniper, and possible-sniper labels. Prowl also prints a chat notice for tagged players with the returned tag type and reason, for example Player tagged for Confirmed Cheater (legit scaffold). A known untagged result gets a green check; a failed or unknown lookup is not represented as an untagged result.

One batch for a rosterThe Urchin request contains multiple players when possible, rather than making a separate request for every name. New results are cached for 20 minutes.

04 / LOAD MANAGEMENT

Cache and request pacing

Hypixel statsCached locally for 24 hours. Saved in config/prowl-stats.properties.
Hypixel request spacingStarts at a 1.2 second minimum gap. When rate-limit headers are present, Prowl adjusts the gap based on the reported limit, remaining budget, and reset time.
429 handlingOn HTTP 429 or a nearly exhausted budget, Prowl pauses requests using Retry-After or the reported reset time and persists the pause in config/prowl-ratelimit.properties.
Urchin tagsCached locally in memory for 20 minutes. Successful batches are separated by at least 2.5 seconds; other errors retry after 30 seconds and HTTP 429 retries after 5 minutes.

Clearing the Prowl roster also clears its local stats cache. A cache hit avoids another Hypixel request until it expires. The rate-limit interval is adaptive, so 1.2 seconds is the starting pace, not a promise that every request will always run at that speed.

05 / IMPORTANT

API keys and policy

Do not enter a Hypixel API key into Prowl v0.1.41.Hypixel's current policy says not to share API keys with third-party mods, including publicly available mods. Prowl v0.1.41 includes a key field and sends that key to Hypixel, so its current stats lookup design conflicts with this policy. Review the official Hypixel API policy. This documentation describes the shipped behavior; it is not an endorsement to enter or share a key.

The Urchin key is stored in Prowl's local settings file, config/prowl.properties, in plain text. Keep that file private and never include it in screenshots, bug reports, or uploads. The public repository contains the website and release JAR only; it does not contain mod source code, personal keys, or local cache/configuration files.

06 / DIAGNOSTICS

When a value is missing

No stats appear
Check /pr status for roster size, key state, queue status, or an active Hypixel cooldown. A fresh cached record will not be requested again until the cache expires.
“No record” appears
The profile resolved, but the API response had no Bed Wars stats record. It can also mean the player has not established a Bed Wars profile.
A nicked player has no stats
Hypixel does not return a usable public player profile for that nick. Prowl leaves the stats unavailable instead of guessing the underlying identity.
Urchin shows a dash or ellipsis
A dash means the lookup is unknown or did not return a usable record; an ellipsis means the lookup has not completed yet. Neither means “confirmed untagged.”
HTTP 429 appears
Hypixel has applied a rate limit. Prowl honors the response's retry/reset timing; repeatedly clearing the roster does not increase the allowed API budget.
